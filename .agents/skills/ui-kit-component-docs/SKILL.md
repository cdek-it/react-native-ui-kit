# Документация компонентов Prime UI Kit

Сверь публичные props, экспорты, defaults, примеры и поведение с исходниками,
тестами и Storybook. За образец бери актуальные Tag, Badge, Button или Input.
Пример другой ветки читай через `git show`, не переключая рабочую область.

## Markdown

Создавай `<Component>.md` рядом с компонентом. Используй только нужные разделы:

1. Название и одно предложение о назначении.
2. `Использование` — минимальный пример с публичным импортом пакета.
3. `Props` — сначала назначение собственного prop, затем существенные варианты,
   defaults (включая встроенные иконки) и ограничения сочетаний. Добавь
   относительную ссылку на публичный тип, для вложенного компонента — на его
   тип.
4. `Доступность` — как получается доступное имя, роли и ответственность
   потребителя. Если разработчику нужно задать имя или учесть другой нюанс,
   добавь короткую рекомендацию с условием её применения. При необходимости
   поясни интерактивного родителя и масштаб шрифта.
5. `Макет` — точная известная ссылка на компонент в Figma.

Стандартные RN props не перечисляй, особое поведение объясняй по месту. Сначала
опиши назначение prop, затем особенности a11y. `accessibilityLabel` описывай в
доступности: различай автоматическое озвучивание компонента и добавление его
смысла потребителем в доступное имя родителя.

## JSDoc И Краткость

Для изменяемого публичного компонента и его собственных props опиши назначение,
смысл callback, controlled-поведение, defaults и существенные ограничения.
Рекомендацию для потребителя повтори в JSDoc соответствующего prop или
компонента, чтобы она была видна при использовании API в редакторе. Добавляй
точную известную Figma-ссылку через `@see`. Для deprecated API укажи замену без
неподтверждённого срока удаления.

Пиши кратко по-русски, без повторов, внутренних функций, токенов, тестов и
хронологии. Сохраняй подтверждённые ограничения: сокращение текста, условия
label/caption, обязательную иконку и доступное имя для iconOnly. Не обещай
непроверенные платформенные возможности.

Совместимость и миграцию не включай в документацию компонента. Если запрошены,
выдай отдельно в чате. README и ссылки из Storybook меняй только по запросу,
сохраняя существующий формат.

## Проверка

Проверь относительные ссылки и точный Figma-узел. Запусти целевой Prettier и
`git diff --check`; остальные проверки и отчёт — по `AGENTS.md`.
